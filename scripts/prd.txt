# Overview
Цель этого документа — описать рефакторинг существующего Telegram-бота ([main.py](mdc:src/main.py)) в более модульную и масштабируемую структуру. Текущая реализация в одном файле затрудняет добавление новой функциональности (как указано в [pyproject.toml](mdc:pyproject.toml): интеграция с RabbitMQ, извлечение данных, управление вакансиями, взаимодействие с пользователями) и поддержку кода. Рефакторинг направлен на разделение логики по соответствующим директориям для улучшения читаемости, тестируемости и общего сопровождения проекта. Изначально поведение бота для конечного пользователя не изменится.

# Core Features (Refactoring)
- **Разделение конфигурации:** Вынести настройки Pydantic ([Settings](mdc:config/settings.py)) и конфигурацию логирования ([logging.py](mdc:config/logging.py)) в отдельный пакет `config`.
- **Изоляция обработчиков:** Переместить обработчики команд (`/my_vacancies`) и сообщений (пересланные, обычные) в соответствующие подпакеты внутри `handlers` ([handlers/commands/vacancies.py](mdc:handlers/commands/vacancies.py), [handlers/messages/forwarded.py](mdc:handlers/messages/forwarded.py), [handlers/messages/regular.py](mdc:handlers/messages/regular.py)).
- **Чистая точка входа:** Переработать корневой [main.py](mdc:main.py), оставив в нем только инициализацию бота, диспетчера, подключение роутеров из `handlers` и запуск опроса.
- **Структура для будущего:** Создать необходимые директории и файлы `__init__.py` для будущих модулей: `middlewares`, `services`, `utils`, `database`, как основу для дальнейшей разработки.

# User Experience
На данном этапе рефакторинга пользовательский опыт взаимодействия с ботом не должен измениться. Команда `/my_vacancies` и обработка сообщений должны работать так же, как и до рефакторинга.

# Technical Architecture
Предлагаемая структура проекта:
```
project_root/
├── config/               # Конфигурация и настройки
│   ├── __init__.py
│   ├── settings.py       # Pydantic Settings класс, загрузка из .env
│   └── logging.py        # Настройка базовой конфигурации logging
├── handlers/             # Основные обработчики Aiogram
│   ├── __init__.py       # Импорт и возможно агрегация роутеров
│   ├── commands/         # Обработчики команд Telegram
│   │   ├── __init__.py
│   │   └── vacancies.py  # Обработчик /my_vacancies, создание router'а
│   └── messages/         # Обработчики сообщений Telegram
│       ├── __init__.py
│       ├── forwarded.py  # Обработчик F.forward_origin, создание router'а
│       └── regular.py    # Обработчик для остальных сообщений, создание router'а
├── middlewares/          # (Placeholder) Мидлвари Aiogram
│   ├── __init__.py
│   └── throttling.py     # (Placeholder) Пример мидлвари
├── services/             # (Placeholder) Бизнес-логика, не зависящая от Aiogram
│   ├── __init__.py
│   └── vacancy_manager.py # (Placeholder) Логика работы с вакансиями
├── utils/                # (Placeholder) Вспомогательные функции
│   ├── __init__.py
│   └── parsers.py        # (Placeholder) Функции парсинга текста сообщений
├── database/             # (Placeholder) Взаимодействие с базой данных (Motor/MongoDB)
│   ├── __init__.py
│   └── crud.py           # (Placeholder) Функции CRUD для вакансий/пользователей
└── main.py               # Точка входа: инициализация Bot, Dispatcher, подключение роутеров, запуск
```
- Файл `src/main.py` будет удален или переименован/перемещен в корневой `main.py` после переноса логики.
- Везде будут созданы `__init__.py` для корректной работы импортов.
- Корневой `main.py` будет импортировать настройки из `config`, инициализировать `Bot` и `Dispatcher`, подключать роутеры из `handlers` и запускать `dp.start_polling()`.

# Development Roadmap (Refactoring Steps)
**Фаза 1: Основной Рефакторинг**
1.  Создать директорию `config` и файлы `__init__.py`, `settings.py`, `logging.py`. Перенести соответствующий код из `src/main.py`.
2.  Создать директорию `handlers` с поддиректориями `commands` и `messages`. Создать все необходимые `__init__.py`.
3.  Создать `handlers/commands/vacancies.py`, перенести туда обработчик `handle_my_vacancies` и создать для него отдельный `Router`.
4.  Создать `handlers/messages/forwarded.py`, перенести `handle_forwarded_message` и создать `Router`.
5.  Создать `handlers/messages/regular.py`, перенести `handle_regular_message` и создать `Router`.
6.  Обновить/создать корневой `main.py`: импортировать `Bot`, `Dispatcher`, настроенный `logging`, настройки `settings`, роутеры из `handlers`. Настроить `Dispatcher`, установить команды бота и запустить поллинг.
7.  Убедиться, что бот запускается и отвечает на команды/сообщения как раньше.
8.  Удалить старый `src/main.py` и `src/__init__.py`.

**Фаза 2: Создание Placeholder Модулей**
1.  Создать директории `middlewares`, `services`, `utils`, `database`.
2.  Создать в них `__init__.py` и пустые файлы-примеры (`throttling.py`, `vacancy_manager.py`, `parsers.py`, `crud.py`) для обозначения структуры.

# Logical Dependency Chain
1.  **Конфигурация (`config`):** Настройки и логирование нужны для всех остальных частей.
2.  **Обработчики (`handlers`):** Перенос и создание роутеров для каждого типа обработчиков.
3.  **Точка входа (`main.py`):** Обновление для использования новой структуры, импорта роутеров и запуска.
4.  **Placeholder Модули:** Создание структуры для будущего развития.

# Risks and Mitigations
- **Риск:** Нарушение работы импортов из-за новой структуры.
    - **Митигация:** Внимательно проверить и обновить все инструкции `import`. Использовать относительные импорты внутри пакетов (`from . import module`) и абсолютные от корня проекта там, где это необходимо (например, в `main.py` при импорте из `handlers` или `config`).
- **Риск:** Случайное изменение логики во время переноса кода.
    - **Митигация:** Переносить код блоками, соответствующими новым файлам. После каждого крупного шага (например, переноса всех обработчиков) запускать бота и проверять его работоспособность (отправлять команды, пересылать сообщения, отправлять обычные сообщения).
- **Риск:** Конфликты имен или неправильное подключение роутеров.
    - **Митигация:** Убедиться, что роутеры создаются в соответствующих файлах `handlers` и корректно импортируются и регистрируются (`dp.include_router()`) в `main.py` в правильном порядке.
- **Риск:** При работе таск мастера LLM начнет генерировать ненужный код или уже сделанные фичи.
    - **Митигация:** Сначала просмотреть все файлы в ./src особенноо ./src/main.py.
